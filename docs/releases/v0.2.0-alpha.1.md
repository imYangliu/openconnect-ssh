# OCH v0.2.0-alpha.1 · Go 命令行版（草案）

配置一次，之后直接运行 `ssh <别名>`。目标端口可达时，OCH 把已建立的 TCP 连接交给 OpenSSH。目标不可达时，OCH 尝试启动 VPN，等待端口可达，再继续同一次 SSH 登录。SSH 密钥和主机指纹仍由 OpenSSH 管理。

## 这版改了什么

- CLI 用 Go 重写，首次运行 `och setup` 在终端逐项配置。移除了 macOS App 和全屏终端控制台。
- 可以通过 `[vpn].helper` 指定已获授权的 VPN 助手。OCH 通过 `sudo -n` 调用它的 connect、status 和 disconnect，凭据和分流路由由助手管理。直接管理 OpenConnect 的用户仍可使用 `sudo -v` 授权。
- `och vpn status` 查看 VPN 状态，`och vpn verify` 单独测试 SSH 目标端口。SSH 会话退出后，其他连接可以继续复用 VPN；用 `och vpn disconnect` 断开。

## 从旧版升级

升级前先用旧版断开 VPN。装过旧 CLI 后台服务的用户应在替换二进制前运行 `sudo och service uninstall`；通过旧 App 注册过服务的用户应在 App 中卸载服务。

原有 config.toml、secrets.env 和旧拼写 `--proxy-command` 可以继续使用。若 SSH 配置里的 ProxyCommand 指向旧 App 或已移动的二进制，更新为新版 och 的绝对路径，并使用参数 `proxy-command %h %p`。可用 `ssh -G <别名>` 检查实际生效的命令。

## 验证范围

在 macOS 上从 VPN 断开的状态使用现有 SSH 别名登录真实目标，确认免密助手启动 VPN、目标路由进入隧道、远端命令成功返回，并在断开后恢复原路由。Linux amd64 已完成交叉编译。
